## 🐧 Handheld Launcher 0.24.3-beta.6 — o launcher já abre no Linux

Beta de correção. O **Windows não muda** (continua igual à 0.24.2 / beta.4 / beta.5).

### O que estava errado (beta.5)
O instalador do beta.5 passou a funcionar: extraía, instalava, criava o atalho, a entrada no menu e o desinstalador. Mas ao executar `handheld-launcher` a aplicação **fechava logo no arranque**:

```
Unhandled exception. System.IO.FileNotFoundException:
Could not load file or assembly 'LibreHardwareMonitorLib, Version=0.9.6.0'
   at HandheldLauncher.App.Services.HardwareMonitorService..ctor()
```

Causa: o pacote NuGet do **LibreHardwareMonitor** só publica binários para Windows (`runtimes/win-x86|x64|arm64`). Compilar para `net8.0` funciona (há referência de compilação), mas ao publicar com `-r linux-x64` esses binários são filtrados — o DLL **não ia** para o pacote, e o código que o usava não estava protegido por plataforma.

### O que muda
- **LibreHardwareMonitor passou a ser só Windows** — referência condicionada à TFM do Windows no `.csproj` e o serviço inteiro dentro de `#if WINDOWS`.
- **Novo `NullHardwareMonitorService`**: no Linux/macOS o launcher arranca normalmente; a temperatura da CPU mostra `--°C` e os alertas de temperatura da Saúde do aparelho ficam desligados (não há leitor de sensores equivalente no pacote). **Todo o resto funciona.**
- **`System.Threading.AccessControl` declarado explicitamente**: chegava de forma transitiva pelo LibreHardwareMonitor; sem ele o build `net8.0` falhava em `RyzenSmuService` (CS1069/CS0103).
- **`handheld-launcher --selftest`** (novo): diagnóstico sem abrir janela — carrega todas as assemblies de que o launcher depende e constrói os serviços de arranque. É a primeira coisa a correr se a janela não abrir; imprime `AUTOTESTE OK` ou exactamente o que falhou.
- **O pacote Linux só é publicado se o `--selftest` passar.** O `scripts/package-linux.sh` extrai o pacote, instala-o num `HOME` temporário e agora **executa a aplicação** em modo autoteste antes de deixar o arquivo ir para a Release. O mesmo teste corre em **todos os envios** (`ci.yml`), por isso esta classe de erro deixa de chegar a você.
- Se a janela não abrir, o instalador já indica o comando de diagnóstico.

### Instalação (Linux)
```bash
tar -xzf HandheldLauncher-linux-x64.tar.gz
cd handheld-launcher
./install-linux.sh          # NUNCA com sudo
```

Depois: procure **"Handheld Launcher"** no menu de aplicações, ou abra um terminal novo e use `handheld-launcher`. Para usar já nesta sessão: `export PATH="$HOME/.local/bin:$PATH"`.

Se algo falhar:
```bash
handheld-launcher --selftest          # diagnóstico rápido
cat ~/.local/state/handheld-launcher/install.log
```

### Requisitos / limitações
- **Zorin/Ubuntu:** `sudo apt install brightnessctl ffmpeg` (e `ryzenadj` só se o APU for AMD). O instalador lista exatamente o que falta.
- **Gamepad:** entre no grupo `input` e reinicie a sessão — `sudo usermod -aG input $USER`.
- **Sensores/TDP no Linux** continuam limitados: temperatura via LibreHardwareMonitor não existe fora do Windows (ver acima) e o TDP depende do `ryzenadj`.
- **LSFG-VK:** precisa do `Lossless.dll` (proprietário) configurado em `~/.config/lsfg-vk/conf.toml`.

### Como reportar
Use **Central de Ajuda → Reportar erro** e anexe o `~/.local/state/handheld-launcher/install.log` **e** a saída de `handheld-launcher --selftest`. Mencione a distro (ex.: Zorin 17) e o que aparece ao rodar `./install-linux.sh` no terminal.

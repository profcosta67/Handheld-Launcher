# installer/

| Arquivo | Pra que serve | Situação |
| --- | --- | --- |
| `InstallTask.ps1` | Roda sozinho depois que o instalador oficial (Velopack, `HandheldLauncher-win-Setup.exe`) instala o app: registra a tarefa `HandheldLauncher_Startup` (abre o launcher no login, como administrador, pro TDP funcionar). Os workflows copiam este arquivo pro pacote. | **Em uso** |
| `Desinstalar.bat`, `Arquivos/Uninstall-Launcher.ps1` | Desfazem o Modo Console e limpam instalações antigas. Vão dentro do pacote `Modo-Console.zip` das Releases. | Em uso |
| `Configurar-Modo-Console.bat`, `Arquivos/Configurar-Modo-Console.ps1` | Troca o shell do Windows pelo launcher (Modo Console), sem passar pelo desktop. | Em uso (opcional, avançado) |
| `install-linux.sh` | Instalador do pacote Linux: copia `arquivos/` para `~/.local/share/handheld-launcher`, cria o atalho `~/.local/bin/handheld-launcher`, a entrada no menu de aplicações com ícone, o atalho no ambiente de trabalho, corrige o `PATH` no `~/.profile`, confere dependências com `ldd` e grava um log em `~/.local/state/handheld-launcher/install.log`. Recusa correr com `sudo`. Opções: `--autostart`, `--no-desktop-shortcut`, `--no-add-path`, `--run`, `--dry-run`, `--prefix`, `--uninstall`, `--help`. | Em uso |
| `menu.sh` | Instalador de **duplo-clique** (o equivalente Linux ao `.bat`): mostra o menu *instalar + arranque no login* / *instalar sem arranque* / *desinstalar* e delega no `install-linux.sh`. `--sem-perguntas` é o modo usado pelo CI. | Em uso (beta.7) |
| `INSTALAR.sh` | Atalho que fica sozinho na raiz do pacote e abre o `instalador/menu.sh`. É um `.sh` com `+x` (e não um `.desktop`) porque um `.desktop` extraído não pode ter caminho absoluto no `Exec` e resolvê-lo com `%k` obriga a `$`/aspas, que o `desktop-file-validate` rejeita. | Em uso (beta.7) |
| `LEIA-ME.txt` | Instruções de 10 linhas que viajam em `instalador/`. | Em uso (beta.7) |
| `uninstall-linux.sh` | Desfaz a instalação Linux (app, atalho, menu, ícone e auto-arranque). Preserva `~/.config/HandheldLauncher` (settings, biblioteca, capas) — `--purge` apaga também. | Em uso |
| `icons/handheld-launcher.png` | Ícone 256×256 (extraído do `Assets/app-icon.ico`) que a entrada de menu usa no Linux. O `scripts/package-linux.sh` copia-o para a raiz do pacote. | Em uso |

O pacote Linux (`.tar.gz` e `.zip`) é montado por [`scripts/package-linux.sh`](../scripts/package-linux.sh) num runner Linux com a estrutura `INSTALAR.sh` + `instalador/` + `arquivos/` (a raiz só tem o atalho, para o utilizador não andar à procura do instalador). O script fixa as permissões (`chmod 755`) antes de compactar, extrai o próprio arquivo gerado e **corre o instalador como o utilizador corre** (`instalador/menu.sh --sem-perguntas`) num `HOME` temporário, exigindo: app instalada, atalho `~/.local/bin`, entrada de menu, ícone, **arranque automático no login**, **atalho no ambiente de trabalho**, `--selftest` OK, opção *sem autostart* a remover o autostart e desinstalação a limpar tudo. O `release.yml` e o `ci.yml` chamam esse script — ou seja, um pacote Linux quebrado falha o workflow em vez de chegar ao utilizador.

O `--selftest` (implementado em `src/HandheldLauncher.App/Diagnostics/StartupSelfTest.cs`) carrega todas as assemblies referenciadas pelo launcher e constrói os serviços de arranque. Foi adicionado no `0.24.3-beta.6`, depois de o beta.5 ter sido publicado com um binário que morria no arranque (`FileNotFoundException: LibreHardwareMonitorLib` — o pacote só publica binários para Windows e o publish `-r linux-x64` não o copiava).

A instalação manual antiga (`Instalar.bat` / `Install-Launcher.ps1`) foi removida na v0.16.4: o `Setup.exe` das Releases faz tudo. O launcher continua limpando sozinho instalações antigas feitas por ela (`LegacyInstallCleanup`).
